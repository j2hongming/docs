    EVPN/VXLAN, BGP AS, MLAG/VRR, VLAN, SVI, VRF

    VLAN（Virtual Local Area Network） 虛擬區域網路。 把一台實體交換機「切」成好幾個獨立的廣播域，就像把一間大教室用透明隔板分成好幾個小班級。不同VLAN的電腦預設不能直接互相看到。 SVI（Switch Virtual Interface） 交換機虛擬介面。 在交換機上，為每個VLAN建立的一個「邏輯 IP 介面」。 它讓交換機可以對這個VLAN做路由（Layer 3），通常用來當該VLAN的預設閘道。 VRF（Virtual Routing and Forwarding） 虛擬路由轉發。 在同一台交換機/路由器上，建立「多套獨立的路由表」。 不同VRF之間預設互相看不到，就像一台機器裡面有多個完全獨立的路由器。 VXLAN（Virtual Extensible LAN） 虛擬可擴展區域網路。 它把原本的Ethernet封包「包起來」（封裝），用UDP/IP的方式穿過Layer 3網路。 解決傳統VLAN只能有4094個、而且不能跨資料中心大範圍的問題（VXLAN可以支援1600萬個）。 EVPN（Ethernet Virtual Private Network） 以太網路虛擬私人網路。 它是 VXLAN 的控制平面（Control Plane）。 使用BGP來學習和通告MAC位址、IP位址，避免傳統的「flood and learn」（廣播氾濫）。讓VXLAN變得更聰明、更有效率。 BGP AS（Border Gateway Protocol Autonomous System） BGP 是網際網路最主要的路由協定。 AS（自治系統） 是BGP裡面的一個「團體編號」。 在資料中心，通常每個Leaf交換機給一個獨立的AS（eBGP），用來建立可靠且可擴展的路由。 MLAG / VRR MLAG（Multi-Chassis Link Aggregation）：多機箱鏈路聚合。讓兩台實體交換機看起來像一台，伺服器可以用LACP把線接到兩台機器，達到主機端冗餘。 VRR（Virtual Router Redundancy，在EVPN環境中常指Anycast Gateway）：虛擬路由器冗餘。讓多台交換機對同一個VLAN使用「相同」的虛擬IP和虛擬MAC作為閘道，實現主動-主動（Active-Active）路由，避免傳統VRRP只能有一台Active。

    這些概念如何統整在一起？（整體關係圖） 在現代資料中心（特別是NVIDIA/Cumulus這類EVPN架構）中，它們的關係通常是這樣的： 基礎層（Underlay）：

    使用 BGP（帶AS） 建立穩定的Layer 3路由骨幹（Leaf-Spine架構）。 提供IP連通性，讓所有交換機可以互相到達。

    虛擬化層（Overlay）：

    VXLAN 負責資料平面（Data Plane）：把L2封包包起來穿過L3網路。 EVPN 負責控制平面：用 BGP 來通告誰在哪裡（MAC、IP、VNI對應），實現自動學習和低氾濫。

    分割與多租戶：

    VLAN：本地交換機上的L2分割。 SVI：讓VLAN可以做L3路由。 VRF：在L3層做更徹底的隔離（不同租戶或部門使用不同路由表）。 EVPN 把這些VLAN對應到 VNI（VXLAN Network Identifier），跨交換機延伸。

    高可用性：

    MLAG：讓伺服器可以同時連兩台Leaf，交換機端冗餘。 VRR / Anycast Gateway：讓兩台Leaf對同一VLAN提供相同的閘道IP，流量可以就近處理，不用繞來繞去。

    整體概念總結： 傳統網路 → 用很多VLAN + STP + MLAG，容易受限。 現代EVPN/VXLAN架構 → 用 BGP（AS） 做Underlay路由 + EVPN 控制VXLAN Overlay + VRF 做租戶隔離 + MLAG/VRR 做冗餘。 這樣就能在大型資料中心裡：

    支援超多虛擬網路 跨機櫃、跨機房延伸L2 同時擁有L2和L3的靈活性 故障時快速收斂 減少廣播風暴

    Think of the data center network as a building.

    VLAN is a room. Devices in the same VLAN are in the same room and can talk directly at Layer 2. Devices in different VLANs are in different rooms and need a router/gateway to talk.

    SVI is the door out of the room. It is the IP address on the switch for a VLAN. Hosts in that VLAN usually use the SVI as their default gateway.

    VRF is a separate building map. A switch can have multiple VRFs, and each VRF has its own routing table. Two VRFs can have separate routes and stay isolated, even on the same physical switch.

    VXLAN is a tunnel between rooms in different buildings. It lets the same VLAN or tenant network exist across multiple switches/racks over an IP network.

    EVPN is the directory that tells everyone where things are. It tells switches: “this MAC/IP lives behind that leaf switch,” so VXLAN traffic knows where to go.

    BGP AS is the routing identity of a switch or group of switches. BGP is how the switches exchange route information. The AS number identifies which routing domain a switch belongs to.

    MLAG makes two switches look like one switch to a server. A server can connect to two switches at the same time using one logical bond, giving redundancy and bandwidth.

    VRR gives hosts one shared gateway IP across two switches. If one switch dies, the other still answers for the same gateway IP.

    Imagine a server is in VLAN 3001.

    The leaf switch has: 

    vlan3001 ip address 192.168.101.254/24
vlan3001 ip vrf VRF-3001
VRF-3001 evpn vni 303001

    • VLAN 3001 is the server’s local network.
    • 192.168.101.254 is the SVI, probably the server’s default gateway.
    • VRF-3001 keeps this network’s routing separate from other networks.
    • VNI 303001 is the VXLAN tunnel ID for carrying that VRF across the fabric.
    • EVPN tells other leaf switches where this VLAN/VRF lives.
    • BGP carries the EVPN information between leafs and spines.

    So when a server in VLAN 3001 on planeALeaf1 talks to another server in the same tenant/network on another leaf:

    1. The packet enters VLAN 3001.
    2. The switch uses the SVI/VRF if routing is needed.
    3. EVPN knows which remote leaf owns the destination.
    4. VXLAN wraps the packet and sends it across the Layer 3 fabric.
    5. BGP is the control-plane protocol that distributed the reachability information.
    6. The remote leaf unwraps the VXLAN packet and delivers it to the destination VLAN.

    For the converged1/2 and borderleaf1/2 pairs, MLAG/VRR add redundancy:

    • A server can connect to both switches using MLAG.
    • The server still sees one logical network connection.
    • The gateway IP can be shared, like 10.10.10.254 or 10.10.30.254.
    • If one switch fails, the other can continue forwarding traffic.

    example

    • planeASpine / planeBSpine: EVPN/VXLAN spines in BGP AS 65000. They use loopbacks 10.255.255.1-4, enable VXLAN/NVE, adaptive routing, and unnumbered eBGP peers on many swps interfaces.
    • planeALeaf / planeBLeaf: EVPN leafs in AS 65101-65108, with loopbacks 10.1.255.1-8. They define L2 VNIs for VLANs 81-96 and 3001-3033, plus L3 VRFs like VRF-3001 through VRF-3033 with VNIs 303001-303033. VLANs 81-96 are grouped under VRF-TEST using VNI 99999.
    • converged1/2: an MLAG pair with many server-facing bonds, VLANs 10, 20, 30, 200-299, 1001-1009, and 1188. They provide VRR anycast gateways ending in .254, local SVI IPs ending in .252/.253, RoCE, BGP AS 65000, and static default routing toward 10.10.10.1.
    • borderleaf1/2: another MLAG/VRR pair for VLANs 10/20/30, with VLAN 30 VRR gateway 10.10.30.254 and default route to 10.10.30.1. borderleaf1 has BGP AS 65001; borderleaf2 does not show a BGP stanza in its running-config.
    • OOB1/2/3: simple out-of-band management switches. They bridge access ports, have VLAN1 SVIs 10.10.30.243, .242, .241, use gateway 10.10.30.254, and keep eth0 on DHCP in the management VRF.
    • rack5compute1/2: compute-side switches with a large bond across many breakout ports, RoCE lossless enabled, and mostly L2 bridge-domain config.
